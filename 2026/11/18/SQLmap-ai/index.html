SQLMap Kali 入门与本地靶场实战

SQLMap 是一个自动化 SQL 注入检测与验证工具。它最有价值的地方，是帮助你确认某个参数是否存在 SQL 注入、识别数据库类型，并在授权范围内证明漏洞影响。

这份教程只在本机 DVWA 靶场中操作。不要对学校、公司、别人的网站或随机公网站点直接运行 SQLMap。

参数 用途
-u 指定目标 URL
-p 只测试指定参数

--risk 测试风险，默认 1，最高 3
-v 显示详细请求和判断过程
--flush-session 清除缓存后重新测试

9. 常见报错怎么排查

all tested parameters do not appear to be injectable

优先检查请求是否完整，而不是马上把 --level 和 --risk 拉满：

重点看：

  • 请求是否被重定向到 /login.php。
  • Cookie 是否仍是登录状态。
  • CSRF Token 是否每次请求变化。
  • 参数名是否写错。
  • 服务器是否限制了频率。

HTTP 403 或被拦截

确认 Cookie、User-Agent、Referer 等请求头是否完整，优先用 -r 复现浏览器请求。只在自己有权限的环境里排查 WAF。

10. 参数不要乱拉满

--level 增加的是测试数量、请求量和等待时间；--risk 增加的是测试载荷可能造成影响的程度。

  • 一般授权测试先使用 --level=1 --risk=1。
  • --risk=2 会增加耗时测试。
  • --risk=3 可能包含可能修改数据的测试，不应在普通业务系统上随手使用。
  • --threads 不是越高越好，靶场演示也建议从 1 到 3 开始。

本教程不需要 --os-shell、--file-read、--file-write 等更高影响能力。学到数据库枚举和结果验证，已经足够理解 SQLMap 的工作方式。

最重要的习惯不是记住更多参数，而是每次都能回答三个问题：目标是否在授权范围内、请求是否完整、我现在做的操作是否必要。
