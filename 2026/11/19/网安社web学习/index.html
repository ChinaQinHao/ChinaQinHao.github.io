原理总结

本题属于典型的 PHP 代码执行漏洞：

  1. 用户输入通过 $_GET['rce'] 被直接接收；
  2. 输入没有经过校验或过滤就传入 eval()；
  3. eval() 将输入解析成 PHP 代码并执行；
  4. 攻击者因此可以调用 PHP 的文件读取函数获得敏感文件内容。

原理总结

本题包含两个典型知识点。

1. 前端限制不等于安全限制

禁用右键、F12 和快捷键只能增加普通用户操作难度。HTML、JavaScript 和隐藏链接仍然会完整发送到客户端，使用 curl、代理工具或浏览器开发者工具都可以查看。

2. 黑名单过滤 eval() 没有安全意义

eval() 会执行任意 PHP 代码。简单的关键词黑名单很容易通过以下方式绕过：

  • 字符串拼接；
  • 大小写变化；
  • 编码与解码；
  • 动态函数调用；
  • 变量和常量替换。

即使过滤了 flag，仍然可以使用其他方式访问文件系统，因此不能把关键词过滤当作安全边界。

修复建议

  • 不要对用户可控内容使用 eval()；
  • 如有动态表达式需求，应使用受限表达式引擎和严格白名单；
  • 如果业务只需要读取固定文件，应使用文件标识映射，而不是接受路径或代码；
  • 不要依赖前端 JavaScript 隐藏链接、禁用快捷键或屏蔽右键；
  • 敏感文件应通过权限控制保护，不应仅依靠输入关键词过滤。

原理总结

本题属于 敏感文件泄露 / 信息收集。

robots.txt 通常不会在网页正文中显示，也通常不会被页面源码引用，但任何访问者都可以直接请求它。CTF 中看到“爬虫协议”“搜索引擎规则”等提示时，应优先检查：

同时还可以检查：

常见误区

  • robots.txt 不是访问控制机制，Disallow 只是对遵守协议的爬虫提出建议；
  • 即使目标路径被写入 Disallow，普通用户仍然可以尝试直接访问；
  • 只查看页面正文或 HTML 源码可能漏掉独立存在的文本文件；
  • robots.txt 位于站点根目录，不在当前页面所在目录。

修复建议

  • 不要把 flag、密码、密钥、内部路径或调试信息写入 robots.txt；
  • 敏感目录应使用真正的身份认证和权限控制，而不是依赖 Disallow；
  • 上线前检查 robots.txt、sitemap.xml、备份文件和源码文件等公开资源；
  • 如果不希望某个目录被索引，同时又不允许公开访问，应使用服务器鉴权或网络访问控制。

本题依次检查下列内容：

顺序 服务端要求 实际设置
1 GET 参数 hello=web 请求 URL 使用 /?hello=web
2 POST 参数 http=good 请求体设置 http=good
3 Cookie Cookie: Sean=god
4 Safari 浏览器 User-Agent: Safari
5 从指定站点访问 Referer: www.mihoyo.com
6 使用 Clash 代理 Via: clash

注意两个容易出错的地方：

  1. Referer 这里要写成 www.mihoyo.com，不要自动补 http://；
  2. Via 的值是小写 clash，实测 Clash 不会通过。
