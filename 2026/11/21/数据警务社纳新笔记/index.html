1.3 HTTP 状态码

状态码 含义 实操中的用途
200 成功 页面或文件可访问
204 成功但无正文 常用于 favicon 或空响应
301/302 永久或临时跳转 可能跳登录页、后台页
401 需要认证 可能需要登录或凭据
403 禁止访问 存在资源，但当前权限不足
404 资源不存在 路径可能错误或文件不存在
500 服务器内部错误 参数可能触发了后端异常

1.4 curl 通用参数

解析：

  • -i：显示响应头。
  • -I：只发送 HEAD 请求并显示响应头。
  • -v：显示请求和响应细节。
  • -L：跟随跳转。
  • -s：静默模式，减少进度信息。
  • -S：配合 -s，仍显示错误。
  • -o file：把响应正文保存到文件。
  • -c cookies.txt：保存服务器返回的 Cookie。
  • -b cookies.txt：读取 Cookie 发送请求。

6.7 XSS 的三种类型

类型 特征
反射型 payload 出现在当前响应中
存储型 payload 被保存，之后其他人查看时执行
DOM 型 浏览器端 JS 从 URL、存储等位置读取数据并写入 DOM

6.8 修复

  • 根据输出上下文进行编码。
  • HTML 正文使用 HTML 实体编码。
  • 不把不可信内容直接写入 innerHTML。
  • 使用 textContent 等安全 DOM API。
  • 设置 CSP。
  • Cookie 使用 HttpOnly、SameSite、Secure。

10. 最后的高频判断

  • grep 搜内容，find 找文件，rg 更快搜源码。
  • -i 是 curl 显示响应头，不是“忽略证书”。
  • -k 是忽略 TLS 证书，只在本地靶场使用。
  • -I 是 HEAD 请求，不返回完整正文。
  • -G 加 --data-urlencode 适合测试 GET 参数。
  • -c 保存 Cookie，-b 携带 Cookie。
  • Nmap -p 指定端口，-p- 扫描全部 TCP 端口。
  • Dirsearch -u 指定 URL，-r 通常是递归。
  • 上传题的 MIME 检查看 Content-Type。
  • SQL 注入的根因是用户输入改变 SQL 结构。
  • sleep() 是时间盲注函数，不是报错注入函数。
  • XSS 要看输出上下文，不是只过滤 <script>。
  • CSRF 不需要读取 Cookie，只需要让浏览器自动携带 Cookie。
  • 修改数据的接口不应该用 GET。
  • 修复 SQL 注入使用参数化查询。
  • 修复 XSS 使用输出上下文编码。
  • 修复 CSRF 使用随机 Token、SameSite 和敏感操作二次确认。
