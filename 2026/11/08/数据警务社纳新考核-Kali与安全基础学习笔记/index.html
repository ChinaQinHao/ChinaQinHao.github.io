2. 安全底线和实验环境

Kali 是合法授权的安全测试系统，不是“自动入侵器”。做任何扫描、爆破或漏洞验证前，必须确认目标属于：

  1. 自己搭建的虚拟机或靶场。
  2. 明确授权的比赛、课程或实训平台。
  3. 明确获得书面授权的测试目标。

不要扫描学校、运营商、公共网站、陌生公网 IP 或他人设备。未经授权测试，即使只是跑一条 nmap，也可能违反规定和法律。

2.1 Kali 虚拟机的安全设置

首次启动后建议先做快照，之后每完成一个实验阶段再创建快照：

  1. 虚拟机网络优先使用 NAT。
  2. 只把靶场虚拟机放在同一个 Host-only 或 NAT 网络中。
  3. 不要在宿主机存放无关隐私文件。
  4. 实验前拍快照，实验后能快速恢复。
  5. 靶场不要直接暴露到公网。
  6. 不把真实密码、Cookie、令牌写进公开博客。

2.2 每次实验前的四问

  • 目标是谁？是否由我控制或明确授权？
  • 我要验证哪一个漏洞假设？
  • 我最多运行哪些命令？影响范围是什么？
  • 出问题后如何恢复快照或停止服务？

4.12 常见 C 语法错误清单

  • if (a = 10) 把赋值当成比较。
  • sum =+ i 不是 sum += i，前者的意思是 sum = +i。
  • 数组循环写成 i <= n 导致越界。
  • scanf("%d", n) 少了 &n。
  • 语句末尾漏分号。
  • else 后面多写分号。
  • 函数名拼错，例如 main 写成 mian。
  • 调用了函数但没有包含对应头文件。
  • 变量未初始化就参与计算。
  • 整数除以零。
  • 字符串数组没有给 '\0' 留空间。
  • 使用 %s 输出没有结束符的字符数组。
  • 函数需要指针，却传入普通值。

6.4 Burp Suite

需要掌握四个界面：

  1. Proxy：浏览器经过 Burp 代理后，拦截和查看 HTTP 请求。
  2. HTTP history：查看已经通过的请求。
  3. Repeater：手动修改一个请求并反复发送，适合验证 SQL 注入、上传类型、参数变化。
  4. Intruder：对固定位置自动替换 payload，模拟批量尝试。

Intruder 攻击模式：

模式 含义
Sniper 通常逐个位置替换同一个 payload
Battering ram 多个位置同时使用同一 payload
Pitchfork 多个位置各用不同字典，按行对应
Cluster bomb 多个字典做笛卡尔积，组合数量最大

历史题中“各位置从不同字典取值并做交集式对应”对应 Pitchfork。

浏览器代理配置的核心：

  1. Burp Proxy 监听 127.0.0.1:8080。
  2. 浏览器代理指向该地址。
  3. 访问 HTTP 靶场，观察请求。
  4. HTTPS 实验需要正确安装和信任 Burp CA 证书。

  • 重命名文件，不直接使用原文件名。
  • 文件保存在 Web 根目录之外。
  • 禁止上传目录执行脚本。
  • 同时验证扩展名、内容、文件大小和解析结果。
  • 对图片重新编码，而不是仅检查 MIME。
  • 上传接口需要身份认证、权限控制和审计日志。

9. XSS、SSRF 和常见 Web 漏洞辨析

9.1 XSS

XSS 是跨站脚本漏洞。攻击者让恶意脚本进入页面，其他用户浏览页面时脚本在浏览器中执行。

三种常见类型：

  • 反射型 XSS：恶意输入立即出现在响应中。
  • 存储型 XSS：恶意内容存入数据库，之后展示给其他用户。
  • DOM 型 XSS：前端 JavaScript 不安全地处理输入并写入 DOM。

  • 根据上下文进行 HTML 编码。
  • 不把不可信字符串直接写入 innerHTML。

  • 设置合理的 CSP。
  • 会话 Cookie 使用 HttpOnly、Secure、SameSite。

9.2 几个容易混淆的漏洞

漏洞 核心问题
SQL 注入 输入改变了 SQL 结构
XSS 恶意脚本在浏览器中执行
文件上传 不可信文件进入服务器并可被访问或执行
SSRF 服务器被诱导访问攻击者指定的地址
CSRF 借用户已登录状态，让浏览器替用户发出非预期请求

9.3 SSRF

SSRF 的重点是“服务器发起请求”。常见危险代码：服务器接收 URL，然后由后端访问该 URL，但没有限制目标地址。

防御包括：

  • 使用明确的目标域名白名单。
  • 禁止访问内网、回环和云元数据地址。
  • 解析 DNS 后再次检查最终 IP。
  • 限制协议、端口、重定向和响应大小。

11. 法律法规和安全职业边界

历年题中涉及《网络安全法》《互联网新闻信息服务管理规定》《互联网跟帖评论服务管理规定》等内容。最需要掌握的不是死记条文序号，而是以下边界：

  1. 网络空间主权、国家安全和社会公共利益受法律保护。
  2. 网络安全工作要保护公民、法人和组织合法权益。
  3. 网络服务需要依法开展安全教育、风险防范和内容管理。
  4. 对严重失信用户可能采取名单管理。
  5. 重大突发社会安全事件处置可能依法采取临时网络措施。
  6. 技术能力必须建立在授权、合规和证据意识上。
  7. 发现漏洞应报告和协助修复，不应下载数据、破坏系统或公开敏感信息。
  8. 实战记录要避免暴露真实密码、个人信息、内网地址和业务数据。

考试中看到“未经授权扫描、下载数据库、上传木马、破坏服务”等选项，应优先判断为不合规行为。

15. 高频速记清单

C 语言

  • main 是入口。
  • C 区分大小写。
  • = 是赋值，== 是比较。
  • 八进制以 0 开头，十六进制以 0x 开头。
  • 数组下标从 0 开始。
  • 字符串以 '\0' 结尾。
  • 普通参数是值传递，修改原变量需要指针。
  • break 跳出循环，continue 跳过本轮。
  • &&、|| 有短路。
  • int 除法会截断。
  • 浮点数不要直接用 ==。
  • 越界、未初始化指针、除零都可能造成未定义行为。

Linux

网络

  • TCP 三次握手。
  • HTTPS 使用加密协议。
  • RDP 默认 3389。
  • HTTP 默认 80，HTTPS 默认 443。
  • 状态码 200 成功，302 重定向，401 未认证，403 禁止，404 不存在，500 服务器错误。

Web 漏洞

  • SQL 注入：输入改变 SQL 结构。
  • XSS：输入变成浏览器脚本。
  • 文件上传：不可信文件进入服务器。
  • SSRF：服务器访问攻击者指定的地址。
  • CSRF：借用户登录态发出非预期请求。

工具

  • Nmap：端口和服务识别。
  • Burp Proxy：拦截和观察请求。
  • Burp Repeater：手工反复修改请求。
  • Burp Intruder：自动替换 payload。
  • Dirsearch：目录和文件发现。
  • Wireshark：观察网络流量。

16. 历年题中的关键判断

这些是帮助你建立题型意识的代表性结论，不应只看答案而跳过原理。

2024 年

  • TCP 保证连接可靠性最典型的基础机制是三次握手。
  • 文件上传漏洞不是因为“没装某个安全软件”，而是校验、保存位置和执行策略不安全。
  • Burp Intruder 中 Pitchfork 对应不同位置使用不同 payload 集合并按行对应。
  • RDP 端口为 3389。
  • HTTPS 属于加密协议。
  • Content-Type 绕过最常见的是抓包修改 MIME 类型。
  • 报错注入常见函数是 updatexml()、extractvalue()、floor()，sleep() 属于时间盲注。
  • 单引号报错只能作为 SQL 注入线索，还要结合响应变化和源码确认。
  • 出现多行结果时，需要 LIMIT 控制一次取一行。
  • concat() 负责连接字符串。
  • XSS 的核心是脚本进入页面并在浏览器执行。

2023 年

  • 普通函数参数交换失败，因为只交换副本。
  • 数组越界、scanf 地址错误、赋值当比较、漏分号都是常见代码错误。
  • 文件上传黑名单只列出 .asp、.aspx、.php、.jsp 时，.png 通常能通过扩展名检查。
  • substr($date, 5, 2) 可从 YYYY-MM-DD 中取月份。
  • 合法 IPv4 每组范围是 0-255。
  • 浏览器弹窗可用 alert("sjjw666")。
  • CONCAT 把多个字符串连接起来。
  • 外带通信依赖 DNS、HTTP 等可观察通道。

2025 年

  • more 可以分页查看内容。
  • chmod 修改权限，chown 修改属主。
  • userdel -r 删除用户和主目录。
  • cp f1.txt f2.txt 或 cat f1.txt > f2.txt 都能复制内容。
  • tail 查看文件末尾。
  • cd ~John 进入 John 的主目录。
  • ps aux 显示所有用户进程。
  • tar -czvf 创建 gzip 压缩包，tar -xzvf 解压。
  • 权限第三段是属组权限。
  • grep 搜字符串，find 找文件。
  • touch 创建空文件或更新时间戳。
  • top 实时查看进程。
  • /etc 保存配置文件。
  • SQL 注入实操关注联合查询、数据库名、表名、字段名、盲注和 MD5 字典匹配。

2022 年

  • 代码阅读题经常考循环、条件、数组和函数返回值。
  • 渗透客观题重点仍是 SQL 注入、文件上传、DVWA 和目录扫描。
  • 实战题体现完整流程：信息收集 -> 找后台 -> 找上传点 -> 验证并解释结果。
